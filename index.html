/ 核心能力

能开就开，开不了就说开不了

不做“显示成功但实际没生效”的假开关。每一步都有可验证的读数。

SCAN

全盘节点探测

扫描 /sys/class/power_supply，满血模式再深入 /sys/devices/platform，逐个标出存在、只读、可写。

WRITE

写入即校验

按置信度从高到低尝试，写完立刻回读。不匹配立即还原原值，再试下一个候选。

ROLLBACK

原值备份

每次写入前记录原始值，一键关闭即回写；重启后内核也会把所有节点复位。

能力边界：直供电是硬件能力，软件不创造它。

三星部分机型的 slate mode、索尼的 HS Power Control、ROG / 红魔 / 黑鲨的旁路充电，都是厂商固件配合硬件做出来的。没有独立电源路径的机型，任何软件都开不出真旁路，本工具会如实显示失败。

首页 / 产品
PRODUCT

一个工具，
两种权限深度。

残血模式只走 Shizuku 的表层节点，满血模式走 Root 直写内核旁路节点。切换模式时执行身份同步切换，能力边界写在界面上，不藏在代码里。

MODE A

残血模式 · Shizuku

执行身份 uid 2000。只写 charging_enabled、charge_disable、charge_control_limit 这类表层节点，内核旁路节点在列表里标为“残血跳过”，点它会被拦下。

MODE B

满血模式 · Root

执行身份 uid 0。可写 batt_slate_mode、bypass_charging、hs_charge_control 等内核节点，自动尝试实验性节点，扫描范围延伸到平台电源目录。

/ 判定

怎么确认它真的生效

不看文案，看两个硬件读数。

算成功的两个条件

已插电，但状态为“未充电 / 已充满”，不再标记 CHARGING。

电池电流接近 0（约 ±80 mA 内）。调高亮度或跑游戏，电量百分比仍不下降。

出现这些立刻关掉

电流为负且几百 mA：主板还在吃电池，继续写没有意义。

充电状态反复跳变、充电器发烫或重启：节点与内核不兼容，先恢复原值。

从授权到拔线，
四步走完。

顺序不能跳：先拿权限，再选模式，再插线写入，最后靠电流判定。跳过任何一步，看到的都可能只是假状态。

1

拿权限

满血要 Root：Magisk / KernelSU / APatch，点“检测 Root”直到显示 uid=0。残血要 Shizuku：先启动服务，再点授权。

2

选模式

点模式卡的“残血”或“满血”，会重新扫描节点，可写 / 只读 / 残血跳过三种状态立刻变化。

3

插线开启

插上数据线，点“开启直供电”。App 按优先级逐个写入并回读，失败自动还原后试下一个。

4

看电流

电流接近 0 且未充电才算成功；仍在充电或放电，就是这台机器没有这条路。

/ 问答

常见问题

为什么我的手机显示“没有找到可写的节点”？+

三种可能：电源节点没暴露写接口；当前身份权限不够（Shizuku 是 shell，写不了 root 节点）；内核把节点收在 SELinux 域里，连 su 也被拦。前两种可换满血模式再试，第三种只能换机型。

残血模式能真的旁路吗？+

少数机型可以，前提是停充节点落在电源路径上。多数机型停充只是电池不再进电，主板仍从电池取电，电量照样掉。所以残血更适合“限制充电、降低发热”。

会不会把手机写坏？+

只写 sysfs，不动分区、不刷固件、不改内核镜像。写入前记录原值，随时可恢复，重启后内核也会复位。风险主要是写错节点导致充电异常或掉电重启，长按电源键重启即可。

支持 iPhone 吗？+

不支持。iOS 没有开放对应接口，也没有 Root 生态，只能靠优化充电限制到 80% 减少损耗。

为什么官网写 12 个节点，App 里看到更多？+

12 个是内置候选表。App 还会扫描所有含关键字的节点，按文件名推断语义后标为实验性，可手动读写。

需要联网吗？会上传数据吗？+

不需要。App 未申请网络权限，节点信息、日志、备份全部留在本机 SharedPreferences 与内存中。

首页 / 关于
ABOUT

一个电源节点的
读写与验证工具。

它不“解锁”硬件，也不承诺通吃。它的全部工作是：找到本机暴露的电源节点、按优先级写入、回读校验、记录原值、随时回滚。

我们做什么

把厂商已经做进固件的直供电能力，用 Root / Shizuku 的写权限调出来，并用实时电流告诉你它到底有没有生效。

对没有这条路的机型，如实报告失败，而不是伪造一个“已开启”的状态。

我们不做什么

不改分区、不刷固件、不替换内核、不注入系统进程；不申请网络权限，不上传任何设备信息；不承诺任何机型一定生效。
